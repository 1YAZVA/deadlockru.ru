# DeadlockRU — переезд на GitHub Pages: инструкция для владельца

Вы делаете три вещи: **(1)** залить код в GitHub, **(2)** нажать пару кнопок в настройках,
**(3)** один раз создать функцию в Яндекс.Облаке. Всё остальное — собирается и работает само.

Архитектура (что где живёт):

```
deadlockru.ru ──► GitHub Pages (сайт + данные: файлы, обновляются Actions каждые 2 часа)
                   └─ вкладка «Аккаунт» ──► функция Яндекс.Облака (живой поиск статистики)
```

Всё бесплатно. DNS менять почти не надо: A-записи уже смотрят на GitHub — правильно.

---

## ЧАСТЬ 1. GitHub (15 минут)

### Шаг 1. Создайте новый репозиторий

1. Откройте github.com → плюс в правом верхнем углу → **New repository**.
2. Name: `deadlockru`. Public (нужно для бесплатных Pages и Actions).
3. Не добавляйте README. **Create repository.**

### Шаг 2. Залейте код

Распакуйте архив `deadlockru-github-ready.zip` — внутри проект + `.github` + `yandex-function` + этот файл.

Вариант А — отдать архив вашему GitHub-агенту со словами: «распакуй в новый репозиторий deadlockru, запушь в ветку main».
Вариант Б — самому (терминал, из папки распакованного архива):

```bash
git init -b main
git add -A
git commit -m "DeadlockRU — статическая версия для GitHub Pages"
git remote add origin https://github.com/ВАШ_НИК/deadlockru.git
git push -u origin main
```

### Шаг 3. Включите Pages (важно!)

1. В репозитории: **Settings → Pages** (слева в разделе Code and automation).
2. **Build and deployment → Source: выберите «GitHub Actions»** (не «Deploy from a branch»!).
3. Внизу той же страницы, поле **Custom domain**: впишите `deadlockru.ru` → Save.
   (Подождите проверку DNS — записи уже правильные, проверка пройдёт за минуты.)
4. Когда появится галочка Enforce HTTPS — включите её.

**Если deadlockru.ru был прописан в настройках Pages старого репозитория (мини-сайт) —
уберите его там**, иначе два репозитория будут спорить за один домен.

### Шаг 4. Первый запуск

1. Вкладка **Actions** в репозитории → выберите workflow «build & deploy (GitHub Pages)» →
   **Run workflow** → Run.
2. Первый прогон самый долгий (скачивает ~700 картинок, ~10–20 минут). Смотрите зелёные галочки.
3. После него сайт живёт на `https://1yazva.github.io/deadlockru/` и на `https://deadlockru.ru`.

Дальше всё автоматом: каждые 2 часа Actions сам обновляет данные; каждый ваш push — пересборка.

## ЧАСТЬ 2. Яндекс.Облако — моторчик для вкладки «Аккаунт» (30 минут, один раз)

Без этого работает весь сайт, КРОМЕ вкладки «Аккаунт» (поиск статистики игроков) —
её обслуживает эта функция. Функция спит, просыпается при запросе, за простой не платит.

### Шаг 1. Регистрация

1. console.yandex.cloud → войти Яндекс-аккаунтом → **Создать облако** (имя любое).
2. Внутри облака → **Создать каталог** (имя `deadlockru`).
3. Создайте **биллинг-аккаунт** (Консоль управления → Биллинг): привяжите банковскую карту.
   Списаний не будет — наш тариф полностью бесплатный (1 млн вызовов функции в месяц,
   мы тратим доли процента).

### Шаг 2. Создайте функцию

1. В каталоге: **Cloud Functions → Функции → Создать функцию**. Имя: `deadlockru-api`.
2. Тип: **Function**. Runtime: **Node.js 20** (или 22).
3. Код: **Загрузить ZIP-архив** → выберите `yandex-function.zip` из распакованного архива.
4. Точка входа: `index.handler`. Память: 256 МБ. Таймаут: 60 сек.
5. Нажмите **Создать версию**.
6. На странице функции: включите **«Все имеют право вызывать функцию»** (публичный доступ).
7. Скопируйте ссылку функции вида `https://functions.yandexcloud.net/b1gxxxxxxxxx`.

### Шаг 3. Проверка

Откройте в браузере `https://functions.yandexcloud.net/b1gxxxxxxxxx/health` —
должен показаться JSON `{"ok":true,...}`.

### Шаг 4. Подключите функцию к сайту

1. GitHub → репозиторий deadlockru → **Settings → Secrets and variables → Actions** →
   вкладка **Variables** → **New repository variable**:
   - Name: `API_BASE`
   - Value: `https://functions.yandexcloud.net/b1gxxxxxxxxx` (ваша ссылка, БЕЗ слэша на конце)
2. Вкладка Actions → запустите workflow ещё раз (Run workflow).
3. Откройте deadlockru.ru → вкладка **Аккаунт** → введите ник любого игрока → статистика грузится.

Готово. Сайт полностью собран.

## Что работает как раньше, что изменилось

| Раздел | На GitHub-версии |
|---|---|
| Главная, герои, предметы, гайды, команды, рулетка, квиз | работает полностью, как было |
| Мета, лидерборд, новости, киберспорт | работает; обновляется Actions-ом каждые 2 часа |
| Живые матчи | снимок на момент последнего обновления (раз в 2 часа) |
| Аккаунт (поиск статистики) | через Яндекс-функцию — как на серверной версии |
| Картинки | лежат прямо на GitHub Pages (зеркалированы) — грузятся всем, включая РФ |

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Actions падает на «Синк данных» | вкладка Actions → лог красного шага; чаще всего сеть API моргнула — просто перезапустите Run workflow |
| Сайт открылся, но данные старые | норм до первого зелёного прогона Actions |
| Вкладка «Аккаунт» пишет ошибку | проверьте переменную API_BASE (Settings → Variables) и что функция публичная |
| Домен не открывается | Settings → Pages: домен прописан? DNS: A-записи 185.199.108–111.153 на месте? (они у вас уже есть) |
| Мини-сайт пропал с deadlockru.ru | это ожидаемо: домен теперь показывает большой сайт; мини-сайт остался на 1yazva.github.io |
